CH.01 VPN Fundamentals

🌐 What Is a VPN?

A Virtual Private Network (VPN) extends a private network across a public one — typically the internet — creating a logical, secure channel between two endpoints so that devices communicate as if they were directly connected on a private link.

🚇
Analogy: Think of the internet as a busy public street. A VPN is like building a private, underground tunnel beneath it. Your car (data) travels the same road network, but no one above ground can see you or where you're going.

The word "Virtual" means there is no dedicated physical wire — it reuses shared public infrastructure. "Private" means the data is protected from unauthorized access.

The 3 components of the name: Virtual (no physical link, uses shared infrastructure) → Private (protected from unauthorized access) → Network (multiple devices/sites unified)

How a VPN Works — Step by Step

  1. User's device initiates a connection to a VPN server.
  2. An encrypted tunnel is established between device and server.
  3. All outbound traffic is routed through this tunnel — it's unreadable to any interceptor.
  4. The user is assigned a virtual IP address, masking their real address.
  5. To the destination server, all traffic appears to originate from the VPN server's IP.

The Four Core VPN Functions

🔒 Encryption — Transforms readable data into ciphertext; protects confidentiality.
🛡️ Integrity — Detects whether data was tampered with in transit.
🪪 Authentication — Confirms only authorized users/devices can connect.
🎭 IP Masking — Hides the real IP behind the VPN server's address.

Why VPN Matters — The Problem it Solves

Public networks (especially open Wi-Fi) are inherently insecure. Without a VPN, data is exposed to eavesdropping, man-in-the-middle (MITM) attacks, and unauthorized surveillance.

📦 Types of VPNs

1. Remote Access VPN

Designed for individual users who need to connect securely to an organization's network from a remote location (home, travel, public network). The VPN authenticates individual users and encrypts all traffic between the user's device and the network.

  • Authenticates individual users before granting access
  • Examples: Cisco AnyConnect, OpenVPN, WireGuard
  • Widely used for remote/hybrid work
🏠
Analogy: Like a remote employee using a special key card to access the company building from home — they get all the access as if they were physically in the office.

2. Site-to-Site VPN

Connects entire networks (not individuals) across the internet. Typically deployed between geographically separated company branches. VPN gateways at each site handle all encryption/decryption transparently — end-user devices need no special VPN configuration.

🏢
Analogy: Two office buildings connected by a private underground pipeline. Employees in each building just use their normal computers — the pipeline (VPN gateway) handles all the secure transport invisibly.

3. Client-to-Site VPN

An individual user installs VPN client software and connects into an enterprise network. IT departments gain granular control over who accesses what. Often paired with Multi-Factor Authentication (MFA).

Key distinction from Remote Access: Client-to-Site emphasizes centralized IT control and policy enforcement, not just basic encrypted remote access.

CH.02 IPsec Architecture

🔐 What Is IPsec?

IPsec (Internet Protocol Security) is a standardized suite of protocols designed to secure IP communications by authenticating and encrypting each IP packet in a data stream.

Critical OSI Layer: IPsec operates at Layer 3 (Network Layer) — unlike TLS which is application-layer. This means it's transparent to applications; no app-level changes are needed.
📬
Analogy: TLS is like sealing each letter individually before putting it in an envelope. IPsec is like securing the entire postal truck — every piece of mail in the truck gets protected regardless of what type of letter it is.

Key Characteristics of IPsec

  • Open standards framework — not proprietary
  • Operates at Layer 3 (Network Layer)
  • Transparent to applications — no app changes needed
  • Supports host-to-host and network-to-network security
  • Core backbone for modern VPN deployments

The 5 Security Services of IPsec

1. Confidentiality — Encrypts packet contents (only authorized recipients can read data)
2. Data Integrity — Ensures data arrives unmodified using cryptographic hash functions
3. Anti-Replay — Prevents attackers from re-transmitting captured valid packets
4. Origin Authentication — Verifies the identity of the communicating party
5. Key Management — Secure generation, distribution, and renewal of cryptographic keys

Confidentiality: How IPsec Encrypts

IPsec uses symmetric-key algorithms (e.g., AES) to encrypt packet payloads. Even if an attacker captures traffic, the ciphertext is unreadable without the correct key.

Symmetric encryption is used (rather than asymmetric) because IP packets may arrive out of sequence and need fast per-packet processing.

Integrity: How IPsec Detects Tampering

IPsec uses cryptographic hash functions (e.g., SHA-256) and Message Authentication Codes (MACs). If the hash computed at the receiver doesn't match the transmitted value, the packet is discarded.

Diffie–Hellman Key Exchange

The Diffie–Hellman (DH) protocol enables two parties to independently compute a shared secret over an untrusted channel — without ever transmitting the secret itself.

🎨
Analogy: Both parties start with a common public color (yellow). Each secretly mixes in their own private color. They exchange the mixed result. Both then add their private color to what they received — both end up with the same final unique color, but a spy who only saw the exchange can never figure out the final combination.
  • Neither party sends the actual key over the network
  • An eavesdropper cannot derive the shared secret
  • DH Groups define key size and algorithm (e.g., Group 14, 19, 20)
  • Foundational to IKE's secure key establishment
CH.03 IPsec Protocols: AH, ESP & Operating Modes

📜 Authentication Header (AH)

AH is one of two core IPsec protocols. It focuses entirely on authentication and integrity — it does NOT encrypt data.

✅ What AH Provides

  • Data origin authentication — verifies who sent the packet
  • Connectionless integrity — detects packet modification
  • Anti-replay protection — uses sequence numbers
  • IP header protection — authenticates the outer IP header

❌ What AH Does NOT Provide

⚠️
AH provides NO encryption. Traffic protected only by AH is readable by anyone who intercepts it — though they cannot modify it without detection.

When to use AH: Environments where integrity and authentication are required but confidentiality is not — such as internal audit trails where data must remain readable by authorized inspectors.

📦 Encapsulating Security Payload (ESP)

ESP is the most commonly deployed IPsec protocol in modern VPNs because it provides full confidentiality through encryption.

🔒 Confidentiality — Encrypts packet payload using AES; data unreadable to eavesdroppers
🪪 Authentication (Optional) — Authenticates origin, verifies integrity using MACs
🔁 Anti-Replay (Optional) — Sequence number tracking to reject duplicate packets
📌 Practical Use — Standard in ALL modern VPN implementations

⚙️ Transport Mode vs Tunnel Mode

Transport Mode

IPsec protects only the upper-layer payload (TCP/UDP data). The original IP header remains intact and visible — source and destination addresses can be seen by routers.

Packet structure: [Original IP Header — visible] → [IPsec Header AH/ESP] → [Encrypted TCP/UDP Payload]
  • Used for host-to-host (peer-to-peer) communication
  • Lower overhead — no additional IP header added
  • Suitable for end-to-end protection within a trusted network
  • Less effective at hiding network topology

Tunnel Mode

IPsec encapsulates the entire original IP packet (including its header) inside a new outer IP packet. A new outer IP header references the VPN gateways — hiding both data and internal network addressing.

Packet structure: [New Outer IP Header — VPN Gateways] → [IPsec Header] → [Encrypted: Original IP Header + Original Payload]
  • Full packet protection — entire original IP packet encrypted and authenticated
  • Outer header contains VPN gateway addresses — internal topology is hidden
  • Primary use case — site-to-site VPN gateways and enterprise deployments

CH.04 IKE Phases & Key Exchange

🤝 IKE — Internet Key Exchange

IKE (Internet Key Exchange) is the protocol responsible for automating the negotiation, generation, and periodic renewal of cryptographic keys for IPsec. It eliminates the need for manual key distribution.

IKE operates in two phases:
  • Phase 1 — Establish a secure authenticated channel between peers (the IKE SA)
  • Phase 2 — Use that secure channel to negotiate the actual IPsec SAs (for data traffic)

Phase 1 — Two Modes

Phase 1 can use either Main Mode (6 messages, more secure, identity protected) or Aggressive Mode (3 messages, faster, identity NOT protected).

FeatureMain ModeAggressive Mode
Messages exchanged63
Identity protectionYes — identity encryptedNo — identity in clear

Key Management and Forward Secrecy

IKE supports forward secrecy — even if long-term keys are compromised, past session keys cannot be derived. It achieves this through Diffie–Hellman key exchanges for each session.

Security Association (SA) — A one-way logical connection between two peers that defines the security parameters (algorithm, keys, lifetime) for that direction of traffic. IPsec needs two SAs for bidirectional communication.
CH.05 Applications & Limitations

🌍 Real-World Applications of IPsec

🏢 Branch Office Connectivity — Site-to-site IPsec tunnels connect offices to HQ without expensive dedicated leased lines
🏠 Secure Remote Access — Gives remote employees encrypted access to internal systems, replacing insecure plain SSH tunnels or unprotected RDP
🔗 Extranet & Intranet — Enables controlled secure communication with trusted external partners (extranet) or between internal segmented business units (intranet)
🛒 E-Commerce Security — Adds an additional network-layer security layer for payment systems and B2B transaction platforms, supplementing TLS

IPsec Limitations

⚠️
Processor Overhead: Encryption, decryption, and integrity checking impose significant CPU load. In high-throughput environments, this reduces effective bandwidth and increases latency unless hardware acceleration (dedicated crypto chips) is deployed.
⚠️
Network Design Complexity: Requires careful planning of Security Associations, key management infrastructure, firewall rules (UDP 500, ESP protocol 50), and NAT traversal (NAT-T). Misconfigurations are a common cause of VPN failures.
  • NAT compatibility requires NAT-T (UDP 4500)
  • Interoperability between vendor implementations can vary
  • Certificate management adds PKI infrastructure requirements

🪤 Common Exam Traps

🚨
TRAP 1: "AH provides encryption" — FALSE. AH provides authentication and integrity ONLY. ESP provides encryption. This is the #1 most common mistake.
🚨
TRAP 2: "IPsec operates at the Application Layer" — FALSE. IPsec operates at Layer 3 (Network Layer). TLS operates at the application layer.
🚨
TRAP 3: "Transport Mode hides the source and destination IPs" — FALSE. Only Tunnel Mode hides internal addresses. Transport Mode leaves the original IP header visible.
🚨
TRAP 4: "Main Mode is faster than Aggressive Mode" — FALSE. Aggressive Mode uses 3 messages (faster). Main Mode uses 6 messages (more secure, slower).
🚨
TRAP 5: "Site-to-Site VPN requires VPN software on each user's computer" — FALSE. The VPN gateways at each site handle everything transparently — end-user devices need no VPN software.
🚨
TRAP 6: "Diffie-Hellman transmits the shared secret over the network" — FALSE. The entire point of DH is that the shared secret is NEVER transmitted. Both parties independently compute it.
